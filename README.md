# 可插件化工作台（Plugin Workbench）

> **一句话**：用一份「工作区包」把任意脚本/命令变成可点击的按钮面板——复制进工作区文件夹就得到功能，点击就**真的在本机执行**，输出实时显示。

桌面软件（Electron）。当前版本 **v0.1**：外壳 + 工作区包（手动复制安装）+ 默认渲染按钮 + **真实执行命令** + 实时输出 + 停止 + 命令可见。

---

## 1. 怎么运行

**开发态（现在）**：

```powershell
git clone <仓库地址>      # 或直接进入已下载的项目目录
cd plugin-workbench
npm install              # 只需第一次（若报错，用 npm.cmd install）
npm start                # 打开软件
```

> `node_modules/` 不进仓库（体积大），**拉下来必须先 `npm install` 一次**。

> ⚠️ 如果 PowerShell 报 "npm.ps1 cannot be loaded ... running scripts is disabled"，
> 改用 `npm.cmd install` / `npm.cmd start` 即可（不动系统策略）。

**打包成安装包（以后）**：`npm run dist`（需要 electron-builder，且要联网下载打包工具）

---

## 2. 软件内部结构（三层）

```
my-app.exe
├── 渲染进程（renderer/index.html）  ← 界面：顶栏 / 工作区列表 / 按钮卡片 / 输出区
│      ⚠️ 被关在沙箱里，没有本机权限
├── preload.js                        ← 安全桥：只暴露几个受控接口给界面
└── main.js（主进程）                  ← 软件后台：有本机权限，负责真的跑命令
```

**设计要点**：**有权限的后台**与**没权限的界面**天然隔离——
界面（以及将来插件自带的自定义界面）**拿不到本机权限**，想执行任何东西都必须通过受控接口请求后台。
这就是"外壳不可改"和自定义界面沙箱能成立的底层原因。

## 3. 安全设置（Electron 侧）

| 设置 | 值 | 为什么 |
|---|---|---|
| `contextIsolation` | `true` | 界面与后台上下文隔离 |
| `nodeIntegration` | `false` | 界面拿不到 Node 能力 |
| `sandbox` | `true` | 界面关进沙箱 |
| 暴露的接口 | 仅 `preload.js` 里列出的几个 | 不给多余能力 |

**执行前可见**：每张卡片都显示"将要执行的命令"，用户装进来之前就能在 `manifest.json` 里看到它要跑什么；软件不隐藏、不代填命令。

## 4. 工作区包格式（产品的核心数据）

一个工作区 = **一个文件夹**（可打包成 `.wsp`，本质是 zip）：

```
我的工作区/
└── manifest.json        ← 必须有
    （将来：ui/ 放自定义界面、assets/ 放图标）
```

`manifest.json`：

```json
{
  "id": "dsh-work",
  "name": "DSH 工作",
  "icon": "🛠",
  "description": "每天用的 DeepSeek Harness 开发工作流",
  "version": "1.0.0",
  "permissions": ["exec"],
  "actions": [
    {
      "id": "dsh-start",
      "title": "启动 DSH",
      "icon": "▶",
      "command": "start \"\" \"启动DSH.bat\"",
      "mode": "service"
    },
    {
      "id": "dsh-tools",
      "title": "在子目录里干活",
      "command": "dir /b",
      "cwd": "tools"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 工作区名称 |
| `actions[]` | ✅ | 动作列表（至少 1 个）|
| `actions[].title` | ✅ | 按钮名 |
| `actions[].command` | ✅ | 要执行的命令 |
| `actions[].cwd` | | 工作目录（可写相对路径，见下）|
| `actions[].mode` | | `task`（跑完就结束，默认）/ `service`（会一直运行）|
| `id` / `icon` / `description` / `version` / `permissions` | | 可选 |

> **这就是"可插件化"的入口**：任何人写一个这样的文件夹，就能给你的软件加功能，不用改你的代码。

### 4.1 命令在哪个目录里跑（很重要）

同一个命令，站在不同目录里跑，结果可能完全不同——`npm run build`、`git status`、以及任何读相对路径的脚本都是这样。所以规则定得很简单：

| 情况 | 工作目录 |
|---|---|
| 没写 `cwd`（**推荐**）| **工作区包自己的目录** |
| `cwd` 是绝对路径（`C:\...`、`\\机器\共享`、`/xxx`）| 就用它 |
| `cwd` 是相对路径（`tools`、`sub\dir`）| 相对**工作区包目录**拼出来 |

**默认值就是工作区包目录**，这条是给"能发布的工作区包"打的地基：作者把脚本和脚本要用的文件一起放进包里，脚本就一定能找到它们；换到别人电脑上、或换个别的位置打开软件，行为都一样。卡片上会写明每条命令将在哪个目录里执行，执行时输出区也会打印真实的工作目录。

**"脚本要处理哪个文件夹"不归软件管**——需要用户挑路径，就让脚本自己弹窗问（见 [§9 第 4 步](#第-4-步需要用户挑路径就让脚本自己弹窗)）。这样脚本在命令行里跑、在别人的机器上跑都一样能用，通用性最高；软件只保证"站在对的目录里把脚本启动起来"。

> 反例（不要这样发布）：把 `cwd` 写死成 `C:\Users\Zhang\Desktop\...`。你自己机器上能跑，别人装上去就是坏的。真要操作某个固定位置，写成一个"只能在本机用"的私人工作区，别分享出去。

### 4.2 包里可以放什么：脚本、exe、资源文件

工作区包**就是一个文件夹**，所以可以往里放任何东西：

```
我的工具/
├── manifest.json
├── tool.exe            ← 现成的 exe 也能直接放进来
├── ffmpeg.exe
├── 模板\报告.html       ← 脚本要读的资源
└── run.ps1
```

命令里用**相对路径**调用它们就行（因为工作目录默认就是包目录）：

```json
{ "title": "跑我的工具", "command": "tool.exe --in 模板\\报告.html" }
```

实测：包里放一个 `hostname.exe`，命令写 `hostname.exe`，点卡片 → 退出码 0、输出 `Y9000P2023`，工作目录显示为工作区包目录。

**边界**：包里放的是"本机可执行的东西"，不需要编译、不需要装运行时；但软件**不会**替你装依赖、也**不会**给 exe 任何额外权限（装进来就是本机权限，v0.1 只保证命令可见）。需要交互输入的程序（要你敲 y/n 的）跑不了——输出区是只读日志，没有给子进程发输入的通道。

## 6. 已知限制（v0.1）

- **中文输出乱码**：已在命令前加 `chcp 65001` 缓解，但个别老程序仍可能乱码。
- **安装靠手动复制**：软件里**没有导入/导出按钮**——把工作区包文件夹复制进 `%APPDATA%\可插件化工作台\workspaces\`，再点「刷新」；`.wsp`（zip）单文件包与其拖拽安装留到下一版。
- **没有托盘/快捷键/开机自启**：Electron 支持，但还没做。
- **`mode: service` 只是声明**：已在清单里预留，界面上的"启动/停止开关 + 运行中的服务面板"还没实现（现在统一用卡片上的"■ 停止"按钮停止）。
- **没有权限沙箱**：v0.1 只做"命令和它的工作目录在卡片上可见"，真正的权限分级/白名单留到后面。
- **软件不提供"选路径"界面**（有意为之）：需要用户挑路径的动作，由**脚本自己弹窗**问（见 §4.1 与 §9 第 4 步）。理由是通用性——脚本在命令行里、在别人的机器上都得能跑，这不该依赖某个软件的专有能力。以后若要做，也只是给"不想写包装脚本"的作者多一个选项，不会替代脚本自己弹窗。

## 9. 从零创建一个工作区（四步）

**第 1 步：建一个文件夹**（文件夹名就是工作区 id）

```
我的工作区\
└── manifest.json
```

**第 2 步：写 `manifest.json`**（最小可用版）

```json
{
  "name": "我的工作区",
  "icon": "🧪",
  "description": "一句话说明这个工作区是干什么的",
  "actions": [
    { "title": "看时间", "icon": "🕐", "command": "echo %TIME%" },
    { "title": "打开桌面", "icon": "📂", "command": "explorer \"C:\\Users\\Zhang\\Desktop\"" }
  ]
}
```

**第 3 步：放进工作区文件夹**

软件**没有**"导入"按钮。工作区靠**手动复制**安装——和 Minecraft 装 mod 一样：

1. 在软件左侧栏底部点一下 **「工作区文件夹」** 下面的蓝色路径，直接打开安装位置：
   `%APPDATA%\可插件化工作台\workspaces\`
2. 把第 2 步做好的**整个文件夹**（里面含 `manifest.json`）复制粘贴进去；
3. 回到软件点顶栏 **「⟳ 刷新」**，新工作区就出现在左栏了。

安装位置与规则：

| 说明 | 内容 |
|---|---|
| 安装位置 | `%APPDATA%\可插件化工作台\workspaces\<工作区id>\`（软件的内置工作区在软件自己的 `workspaces\` 目录下，带「内置」标记） |
| 装进去之后 | 与**原始文件夹无关**了——原文件夹可以移动、改名甚至删除，工作区照常可用 |
| 建议跳过 | 别把 `node_modules`、`.git`、`.vscode` 一起复制进去，那些是开发残留，装了只会拖慢扫描 |
| 同名冲突 | **后放进去的会覆盖先放进去的**——同一个工作区 id 只留一份，改完记得点「刷新」 |
| 卸载 | 卡片上的「✕」会**删除软件目录里的那一份**（不动你的原始文件夹）|

> **提示**：想验证"是不是真在执行"，用 `echo %TIME% %RANDOM%` 这种命令——每次输出的时间和随机数都不一样。

**第 4 步：需要用户挑路径，就让脚本自己弹窗**

如果你想让用户挑一个文件夹（比如"整理我选的那个目录"），**不要指望软件提供选路径的界面**——让脚本自己去问。这样脚本在命令行里跑、在别人的电脑上跑都一样能用，通用性最高。

命令行工具本身不会弹窗（`robocopy`、`ffmpeg`、`git` 都不会），所以这一步由**包装脚本**来做。PowerShell 版：

```powershell
# 脚本自己弹出"选择文件夹"，拿到路径后自己处理
$shell  = New-Object -ComObject Shell.Application
$folder = $shell.BrowseForFolder(0, '选择一个文件夹', 0)
if (-not $folder) { Write-Host '（已取消）'; exit 0 }
$path = $folder.Self.Path
Write-Host ('选中的文件夹：' + $path)
Get-ChildItem -LiteralPath $path | Select-Object -First 20
```

清单里照常写相对路径，脚本就能被找到（因为工作目录默认就是工作区包目录）：

```json
{ "title": "选一个文件夹并列内容",
  "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"pick-folder.ps1\"" }
```

Python 版就是 `tkinter.filedialog.askdirectory()`，同理。

> ⚠️ **写中文脚本的坑**：Windows PowerShell 5.1 读 `.ps1` 时，如果文件**没有 UTF-8 BOM**，里面的中文会按 ANSI 解码，脚本可能直接解析失败。用记事本"另存为"时选 **UTF-8 带 BOM**，或者干脆像上面的例子一样把中文只放在运行期输出里。
> 现成参考：内置工作区 **「路径示例」** 就是这个写法（`workspaces\路径示例\pick-folder.ps1`）。

## 9.1 测试

规则（"命令在哪个目录里跑"）被单独抽成了纯函数 `lib/resolve-run.js`，可以直接跑测试：

```powershell
node test/resolve-run.test.js      # 单元测试：9 项，把默认值/相对路径/绝对路径/报错都钉住
node test/run-in-package.test.js   # 集成测试：真的起进程，验证"站在包目录里就能用相对路径找到脚本"
```

集成测试里有一组对照实验：同一个相对路径脚本，**目录不对 → 找不到**；**用算出来的工作区包目录 → 正常跑完并读到同包的相对数据文件**。这就是默认工作目录这条规则存在的理由。

## 10. 自定义界面：工作区自带界面

工作区可以在清单里声明 `ui`，则**内容区不再使用宿主的默认渲染器**，而是装一个**沙箱 iframe**，渲染工作区自带的页面。

### 清单写法

```json
{
  "name": "霓虹看板",
  "icon": "🌈",
  "ui": { "entry": "ui/index.html" },
  "actions": [
    { "id": "show-time", "title": "看时间", "icon": "🕐", "command": "echo %TIME%" }
  ]
}
```

包结构（界面可以多文件、可用相对路径引资源）：

```
霓虹看板/
├── manifest.json          ← 命令仍然写在这里
└── ui/
    ├── index.html
    └── style.css
```

### 它能自定义什么

**内容区那一块**里的任何东西：背景（含 canvas / WebGL 动画）、布局、配色、字体、按钮位置与样式、图表、拖拽、弹窗……**外壳（顶栏 / 左栏 / 输出区）不可改**。

还能**联网**：自定义界面可以加载 CDN 资源、请求公开 API。实测（临时测试包，界面里 `fetch` 一个公开接口）：✅ HTTP 200、拿到返回内容，约 350ms 返回。

> 注意：沙箱界面的来源是"不透明来源"（`Origin: null`），跨域请求能不能成，取决于对方有没有放开 CORS。

### 安全：三条边界

| 边界 | 做法 |
|---|---|
| **拿不到宿主数据** | iframe 用 `sandbox="allow-scripts"`，**不给** `allow-same-origin`（不透明源 → 访问宿主 DOM、localStorage、cookie 一律失败）|
| **不能直接执行命令** | 界面只能 `postMessage` 请求宿主"帮我跑某个动作"；**执行权始终在主进程**，命令仍以清单为准 |
| **不能读任意文件** | 界面资源经自定义协议 `wsp://local/<工作区id>/<包内相对路径>` 加载，**只允许读该工作区目录内的文件**，并做目录穿越校验 |

> **实测结论**：沙箱 iframe **无法加载 `file://` 资源**（Chromium 报 "Not allowed to load local resource"），因此必须用 `wsp://` 自定义协议。
> 另外：界面**弹不出系统对话框**（所以"选路径"要让脚本自己弹）、**不能开新窗口/打开浏览器**（没有 `allow-popups`，宿主也没提供这个接口）。

### 宿主 ↔ 界面 通信协议（postMessage）

| 方向 | 消息 | 说明 |
|---|---|---|
| 界面 → 宿主 | `{type:'ready'}` | 界面已加载，请求工作区信息 |
| 宿主 → 界面 | `{type:'host-init', workspace, actions[], permissions, theme}` | 派发工作区信息与动作清单 |
| 界面 → 宿主 | `{type:'run', actionId}` | **请求执行**某个动作（由宿主决定并执行）|
| 界面 → 宿主 | `{type:'notify', text}` | 往输出区打一条日志 |
| 宿主 → 界面 | `{type:'action-started', actionId, runId, command}` | 已开始执行 |
| 宿主 → 界面 | `{type:'output', actionId, runId, stream, text}` | 实时输出（stdout / stderr）|
| 宿主 → 界面 | `{type:'action-exit', actionId, runId, code, stopped, duration}` | 执行结束 |

宿主**严格校验消息来源**——只接受自己 iframe 的 `contentWindow` 发来的消息。

### 示例工作区

`workspaces\霓虹看板\`：自带界面 + 动态交互背景 + 自定义卡片与迷你控制台。

> **提示**：大多数工作区不需要自定义界面（默认渲染器更安全，作者也无需写代码）。它是给需要独特外观的作者留的"逃生舱"。

## 11. 发展路线（已定的设计决策）

| # | 决策 | 内容 |
|---|---|---|
| 1 | **定位** | 可插件化工作台（面向市场，先极客后大众）|
| 2 | **边界** | 外壳（宿主专有，插件不可改）+ 内容区（插件声明，宿主渲染）|
| 3 | **自由度** | 声明式配置（宿主默认渲染）+ 自定义界面（沙箱 iframe，已实现）|
| 4 | **打包** | 工作区 = 一个包（`manifest.json` + 可选 `ui/`），手动复制安装，分享用 `.wsp` |
| 5 | **形态** | **Electron 桌面软件** |
| 6 | **顺序** | 声明式配置 → 真实执行 → 自定义界面 → 权限模型 |
